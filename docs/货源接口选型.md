# AgentMall Phase 2 货源接口选型（2026-10-07 调研）

> 调研基于开发者社区整理的官方文档资料（CSDN 博客群、360doc 实操指南）。
> Phase 2 动手前，务必以 open.1688.com 官方文档为准再核一遍接口名与权限。

## 结论

**1688 是 Phase 2 唯一货源，且是唯一解。**

1. 国内唯一同时具备"源头工厂货 + 官方分销 API + 一件代发全链路"的平台。
2. 淘宝 / 拼多多 / 抖店三家官方铺货工具的货源端**全部**是 1688——它是事实上的货源中枢，绕开它等于绕开货源。
3. 日用百货（纸巾/收纳/清洁）正是义乌系强项，货最全、一件代发价最低。
4. 接入成本最低：营业执照 + 企业认证（1–3 工作日），API 调用免费。

## 1688 API 矩阵（Phase 2 要用的）

| 接口 | 用途 | 备注 |
|------|------|------|
| `alibaba.product.search` | 商品搜索（关键词/价格/销量/类目，单次最多 200 条） | 定时批量同步，不做实时查 |
| `alibaba.product.get` | 商品详情（含 SKU/库存） | |
| `alibaba.agent.price.get` | **分销价/一件代发价**（返回 `agentPrice`） | ⚠️ 必须用这个拿价，普通商品接口返回的是批发价，拿错直接亏本 |
| `alibaba.trade.createOrder` | 创建采购订单（单次最多 50 个 SKU） | 即"平台代下单" |
| `alibaba.trade.pay` | 订单支付（对接支付宝/微信） | 平台先收用户款、再付 1688，现金流正向 |
| `alibaba.logistics.trace` | 物流轨迹 | 订单状态回传给智能体 |
| `alibaba.logistics.quotation` | 运费报价 | 比价时计入总成本 |
| `alibaba.trade.refund.apply` | 售后申请 | |
| `alibaba.trade.confirmReceipt` | 确认收货 | |

## 4 个业务坑（技术之外，提前知道）

1. **分销关系要逐商家申请**：调了下单 API 不等于任意商家都给你代发。
   必须先在 1688 向商家申请代销关系、商家同意后才能下单。
   → Phase 2 选品只选明确标注"支持一件代发/分销"的商家，否则订单会黄。
2. **`agent_price` ≠ 批发价**：一件代发价必须调 `alibaba.agent.price.get`，
   普通商品接口拿的是批发价，差价算错直接亏本。
3. **Token 有效期 2–10 小时**：必须做自动刷新 + 失败重试，否则半夜掉线。
4. **免费版限流约 5–10 次/秒**：商品库策略 = 定时批量同步到本地 + 本地缓存，
   智能体查询永远走本地，绝不每次实时调 API。

## 备选（补充位，非替代）

- **拼多多开放平台**：`pdd.ddk.goods.detail`（多多客）只做**比价参考**
  （拼多多零售价是天然价格锚点，智能体可报"比拼多多便宜 X%"），不做货源。
  注意：ddk 是 CPS 推广分佣，不是分销代发。
- **淘宝开放平台**：未来若做"淘宝店分销"业务才用，货源仍回流 1688，现阶段不需要。

## 明确不碰的

- **CPS 类 API 别混淆**：淘宝联盟（tbk）、京东联盟（jd.union）、多多客（ddk）
  都是推广赚佣金，不是拿货代发，看到 `union`/`ddk`/`tbk` 直接跳过。
- **第三方爬虫 API**：市面上的万邦科技类"API"本质是爬虫封装，长期必死。
  用户原话："其他商城去爬数据，不稳定"——官方接口是唯一地基。
- **抖店开放平台**：要软件著作权证书，门槛高，且货源端仍是 1688。
- **爱库存/唯品仓/义乌购/快手**：无公开 API 文档（邀请制或干脆没开放），对接无门。

## 代码映射

Phase 2 实现 `Alibaba1688Source(ProductSource)`（`agentmall/store.py` 已留接口），
内部按上表逐个封装：
`sync_products()`（定时）→ `get_agent_price()` → `create_order()` →
`pay()` → `trace_logistics()` → `apply_refund()`。
tool 层（`server.py`）一字不动——这就是 Adapter 模式的意义。
