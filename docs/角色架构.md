# AgentMall 三智能体角色架构

> 定死，不许混。买的人、卖的人、管平台的人，看到的数据和能做的操作完全不同。
> 混在一起 = 商户能改别人的价格、用户能看到商户成本价 = 灾难。

## 1. 三个角色

### 🛒 用户智能体（Shopper Agent）—— Phase 1（今晚只做这个）
- **功能**：搜索商品、比价、查看详情、创建订单（辅助支付）、查询自己订单、申请退货
- **可见数据**：全平台公开商品信息；自己的订单
- **禁区**：改价、改库存、上架下架、查看他人订单、查看商户成本价

### 🏪 商户智能体（Merchant Agent）—— Phase 2
- **功能**：商品上架/下架、改价、改库存、查看自己店铺订单、发货、处理售后、看自己店铺经营数据
- **可见数据**：自己商户的商品、订单、经营数据
- **禁区**：查看/修改其他商户数据；查看用户隐私信息（收货地址等敏感字段脱敏）；
  查看平台级数据

### 🛡️ 管理员智能体（Admin Agent）—— Phase 2/3
- **功能**：商户入驻审核、商品上架审核、订单风控（异常/刷单检测）、纠纷仲裁、
  平台数据看板、处罚（下架商品、冻结商户）
- **可见数据**：平台级数据（用户隐私字段脱敏后）
- **红线**：所有写操作必须记审计日志（who / when / what）；不能直接操作资金；
  不能替用户下单、不能替商户改价（只能下架/冻结）

## 2. 权限矩阵

| 能力 | 用户智能体 | 商户智能体 | 管理员智能体 |
|------|-----------|-----------|-------------|
| 搜索/浏览商品 | ✅ | ✅ | ✅ |
| 下单 | ✅（仅自己的） | ❌ | ❌ |
| 查询订单 | ✅（仅自己的） | ✅（仅自己店铺的） | ✅（仅风控/仲裁场景，全程审计） |
| 上架/下架商品 | ❌ | ✅（仅自己的） | ✅（仅下架/处罚） |
| 改价/改库存 | ❌ | ✅（仅自己的） | ❌ |
| 商户入驻审核 | ❌ | ❌ | ✅ |
| 平台数据看板 | ❌ | ❌（仅自己店铺） | ✅ |
| 审计日志 | — | — | ✅（只读，且自身操作也被记录） |

## 3. 技术落地（Phase 2，不在今晚）

- **部署形态**：三个独立 MCP Server（或一个 Server + tool 前缀
  `shop_*` / `merchant_*` / `admin_*`），共用 `store.py` 数据层。
- **鉴权**：MCP 连接时声明角色（API Key），Server 按角色过滤可用 tool，
  未授权调用直接拒绝并记日志。今晚的 `store.py` 无鉴权——Phase 1 是单机演示，
  上线前必须补上。
- **审计**：管理员所有写操作落库（`admin_audit_log`），不可删改。

## 4. 今晚（Phase 1）要守的边界

1. 只实现用户侧 4 个 tool（`search_products / get_product / create_order / get_order`）。
2. `store.py` 里**不要**提前写改价/改库存的 tool——即使是"以后用"也别留，
   避免演示时被误调。今晚之后商户侧从零起新文件。
3. 代码注释标好 Phase 2 扩展点（`ProductSource` 适配器已留，见开发任务书 §8）。
