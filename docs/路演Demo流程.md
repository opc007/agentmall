# 路演 Demo 流程（基础雏形）

> 目标：给投资方完整走一遍业务逻辑——从注册到扫码支付完成。
> 演示者：用户本人。智能体：workbuddy（用户自己的 AI，需支持 MCP 接入）。

## 上台前先彩排（别跳这步）

**顺序很重要**：先验，后清。

```bash
./scripts/start_demo.sh --check  # ① 七套测试 + 拿这套服务真跑一遍下面 9 步
./scripts/reset_demo.sh          # ② 验完把演示库清回刚 seed 完的样子（自动备份到 /tmp）
./scripts/start_demo.sh          # ③ 重新起服务，正式开演
```

①里的彩排会逐步打印「你说什么 / 屏幕出现什么 / 怎么说 / 断了怎么救」，
输出在 `/tmp/agentmall_rehearse.log`。它会在演示库里留下一笔彩排单，
所以要跑 ② 清掉——带着别人的测试单上讲，说服力打折。

想单独看每步话术：

```bash
.venv/bin/python scripts/rehearse.py              # 对着已起的服务彩排
.venv/bin/python scripts/rehearse.py --isolated   # 没起服务时，自己拉一套临时的（不碰演示库）
```

> 彩排不是测试。单测全绿不代表台上能演——第 9 步「看板 GMV 增加」就是彩排时才发现
> 当时恒为 0（原因见 `docs/演示脚本v2.md` 附录）。

## 7 步流程

1. **打开网页** → 注册用户（最简：用户名 + 密码）→ 登录
2. **个人中心** → 复制 MCP 接入点（含 URL + 你的 key，一键复制）
3. **把 MCP 接入点配给 workbuddy**
4. **对 workbuddy 说**：「帮我找最便宜的抽纸，30 元以内，送到南宁市朝阳广场」
5. **workbuddy 执行**：`search_products` 搜索 → 比价 → 向你确认 → `create_order` 建单（待支付）
6. **网页订单列表**出现新订单 → 点"去支付" → 显示二维码（prototype 模拟支付，页面明确标注"演示环境"）
7. **扫码**（本地演示时直接点开链接；公网部署后手机扫码）→ 确认支付 ¥xx → 订单状态变为"已完成"

## 验收

- 全程无报错；订单状态机：待支付 → 已完成
- workbuddy 全程只调 MCP，不碰网页（证明"智能体中转"成立）
- 二维码内容 = 支付确认页 URL；确认支付后订单完成，库存已扣减

## 第 8–9 步（管理员视角，P1 完成后演示）

8. 切到管理后台 → 实时看到刚才的订单进来
9. 看板数字变化：订单数 +1、GMV 增加 → 对投资方说"这就是平台侧看到的东西"
