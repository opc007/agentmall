# AgentMall 公网部署文档

> **演示环境声明（重要，先看这段）**
>
> 本项目当前处于**演示/MVP 阶段**：
> - 商品为**演示数据**（`data/products_real.json` 抓取自公开货源页面，仅作展示，不构成真实供货）；
> - 支付为 **Mock 模拟网关**（`agentmall/payment.py` 的 `MockPaymentGateway`），
>   不接入任何真实支付通道，**不发生任何真实交易、不产生任何真实资金流转**；
> - 未接入 1688 等真实货源 API，不产生真实发货。
>
> 下方步骤能让你把这套演示环境挂到公网域名上对外演示/路演。
> **它不等于一个可以直接收真实订单的生产系统**，上线前请逐条走 §8 安全清单。

## 1. 前置条件（硬门槛，先确认再买服务器）

| # | 需要什么 | 说明 / 卡点 |
|---|---|---|
| 1 | **一台有公网 IP 的云服务器** | 最低配：**2 vCPU / 2GB RAM / 40GB 磁盘**。三个 Python 进程常驻 ≈ 400MB~700MB，2GB 内存跑得下且留有余量。系统推荐 **Ubuntu 22.04 LTS** 或 **Debian 12**，本文命令按 Ubuntu/Debian 写。 |
| 2 | **公网 IP，且安全组放行 80 / 443** | 只放这两个端口。8000/8001/8002 **一律不对公网开放**（原因见 §7.3）。 |
| 3 | **一个域名** | 例：`mall.example.com`，解析 A 记录到服务器公网 IP。 |
| 4 | **⚠️ ICP 备案（国内服务器是硬门槛）** | **服务器在中国大陆境内时，域名必须完成 ICP 备案才能用 80/443 对外提供服务。** 没备案的域名解析到境内 IP，云厂商的接入网关会直接拦截，表现为「域名能 ping 通但网页打不开 / 备案拦截页」。备案周期通常 **7~20 个工作日**，须在买服务器后立刻提交，**卡这里最久**。<br>• 备案要求：主体资质（个人或企业）、网站名称、服务器必须在备案接入商（阿里云/腾讯云等）名下。<br>• **绕不过备案的办法**：服务器买**香港/新加坡/美西**等境外节点。境外节点不要求 ICP 备案，域名解析过去即可用，但大陆访问延迟高（香港节点通常 30~80ms，可接受）。<br>• 备案期间可用 IP 直连（`http://公网IP:8000`，仅本机测试）或境外节点过渡。 |
| 5 | **HTTPS 证书** | 公网站点基本必须上 HTTPS（MCP 客户端多数要求 https）。<br>• 有备案域名：Let's Encrypt 免费证书（`certbot`），90 天自动续。<br>• 无备案/境外节点：Let's Encrypt 同样可用（HTTP-01 校验只要求 80 端口能通，不查备案）。<br>• 本文**不代申请任何证书**，只写命令。 |
| 6 | **一个能解析的 MCP 客户端** | 用于验证 `/mcp` 接入。任意支持 MCP streamable-http 的客户端（Claude Code / Cursor / 各类智能体平台）都行。 |

## 2. 环境变量表（**已逐个 grep 代码确认**，不是照抄文档）

|---|---|---|---|---|
| `AGENTMALL_DB` | ✅ `agentmall/db.py:16` | `<包目录>/data/agentmall.db`（即 `/opt/agentmall/agentmall/data/agentmall.db`） | SQLite 文件路径。**三个进程必须指向同一个文件**，否则各建各的库、数据不共享。 | ✅ 必填（显式指到数据目录，别用包目录） |
| `AGENTMALL_MCP_PORT` | ✅ `agentmall/http_server.py:29` | `8001` | MCP streamable-http 服务端口 | ➖ 保持默认即可 |
| `AGENTMALL_ADMIN_PORT` | ✅ `agentmall/web/admin_app.py:216` | `8002` | 管理后台端口 | ➖ 保持默认即可 |
| `AGENTMALL_PUBLIC_URL` | ✅ `agentmall/payment.py:12` | `http://127.0.0.1:8000` | **支付收银台链接的对外 base URL**。下单时用它拼 `pay_url`。 | ✅ **必填，必须是真实公网域名**。不设 → 用户收到的订单链接指向 `127.0.0.1`，在自己电脑上打不开 |
| `AGENTMALL_MULTI_ROLE` | ✅ `agentmall/server.py:65`（`== "1"` 才生效） | 空（单角色裁剪） | 多角色模式：一个 MCP 进程同时注册 user/merchant/admin 三套 tool。**streamable-http 模式必须开**，否则用户 key 调不到订单相关 tool | ✅ MCP 服务设 `1` |
| `AGENTMALL_ADMIN_BASE_PATH` | ✅ `agentmall/web/admin_app.py:34` | 空 | 管理后台对外挂载路径前缀。挂在 `https://域名/admin/` 时必须设成 `/admin`，后台才会生成带前缀的链接。**不设的后果：后台点「订单」会跳到用户面的订单页**（两者都有 `/orders`、`/login` 路由） | ✅ **经 nginx 挂 `/admin` 时必填**；独立子域名部署可留空 |

## 3. 方式 A：Docker Compose（推荐，拿服务器最快上线）

### 3.1 拷代码

```bash
sudo apt update && sudo apt install -y git
sudo useradd -m -d /home/agentmall agentmall   # 已存在可跳过
# 把仓库拉到服务器（内网自建 git / scp / GitHub 都行）
sudo -u agentmall git clone <你的仓库地址> /home/agentmall/agentmall
cd /home/agentmall/agentmall
```

### 3.2 配公网 URL

```bash
cat > .env <<'EOF'
# ⚠️ 必须是真实公网域名，否则订单里的「去支付」链接指向 127.0.0.1
AGENTMALL_PUBLIC_URL=https://mall.example.com
EOF
chmod 600 .env      # .gitignore 已排除 .env，别手滑提交上去
```

### 3.3 数据目录权限（**不做这一步必然起不来**）

```bash
mkdir -p ./data
# 容器内 agentmall 用户的 uid/gid 是 10001（见 Dockerfile 的 ARG）
sudo chown -R 10001:10001 ./data
```

SQLite 文件由容器内非 root 用户创建，宿主目录属主不对就是
`unable to open database file` —— compose 里 `./data:/data` 挂的就是这个目录。

### 3.4 构建 + 起服务

```bash
docker compose up -d --build

docker compose ps           # 三个服务都该是 healthy
curl -s localhost:8000/healthz   # {"ok":true}
curl -s localhost:8001/healthz   # {"ok":true,"service":"agentmall-mcp","path":"/mcp"}
curl -s localhost:8002/healthz   # {"ok":true,"service":"agentmall-admin"}
```

`docker-compose.yml` 里三个 service 已把 8000/8001/8002 都绑到 **127.0.0.1**，
所以外部访问必须过 nginx（`127.0.0.1` 绑定天然挡住公网直连，双保险）。

### 3.5 常用运维命令

```bash
docker compose logs -f web          # 看某个服务日志
docker compose restart mcp          # 重启单个
docker compose down                 # 停止（数据在宿主 ./data，不丢）
docker compose up -d --build web    # 改了 Dockerfile/依赖后重建单个
```

## 4. 方式 B：systemd + venv（不用 Docker 时）

### 4.1 装系统依赖

```bash
sudo apt update
sudo apt install -y python3.11 python3.11-venv python3-pip nginx sqlite3 git
# Ubuntu 22.04 自带 3.10，若需要 3.11：
#   sudo add-apt-repository ppa:deadsnakes/ppa -y
#   sudo apt install -y python3.11 python3.11-venv
python3 --version
```

### 4.2 建用户 + 拷代码

```bash
sudo useradd -m -d /home/agentmall -s /bin/bash agentmall
sudo mkdir -p /opt/agentmall /var/lib/agentmall /etc/agentmall
sudo -u agentmall git clone <你的仓库地址> /tmp/agentmall-src
sudo cp -a /tmp/agentmall-src/. /opt/agentmall/
rm -rf /tmp/agentmall-src /opt/agentmall/.git   # 服务器上不需要 git 历史
sudo chown -R agentmall:agentmall /opt/agentmall
```

### 4.3 建 venv 装依赖（国内加源加速）

```bash
sudo -u agentmall python3.11 -m venv /opt/agentmall/.venv
sudo -u agentmall /opt/agentmall/.venv/bin/pip install -U pip -i https://pypi.tuna.tsinghua.edu.cn/simple
sudo -u agentmall /opt/agentmall/.venv/bin/pip install -r /opt/agentmall/requirements.txt -i https://pypi.tuna.tsinghua.edu.cn/simple
# 海外服务器去掉 -i 参数用默认源即可
```

> ⚠️ **不要动 `requirements.txt` 里 `mcp>=1.8,<2` 这个上限**。
> mcp 2.x 把 `FastMCP` 更名为 `MCPServer`，`mcp.server.fastmcp` 会直接 ImportError，
> `agentmall/server.py` 是按 v1 API 写的，装了 2.x MCP 服务直接起不来。

### 4.4 建库初始化（**首次启动会自动建表 + 灌演示商品**）

不用手动建库。三个服务任一启动时，`lifespan` 里都会调 `db.init_db()`：

1. 建 6 张表（merchants / admin_keys / users / products / orders / audit_log）
   + 审计日志的**禁删改触发器**（合规红线：审计不可篡改）；
2. 灌预置账号与 key（§6 的演示 key）；
3. 灌商品：优先读 `**/data/products_real.json`（当前 59 条抓取商品），
   文件不存在或解析失败才退回 `agentmall/data/products_seed.json`（30 条老种子）。

三种情况都做了保护：`busy_timeout=15000` + WAL + 5 次退避重试，
所以三个服务同时启动撞锁也不会起不来。

**验证建库成功：**

```bash
sudo -u agentmall sqlite3 /var/lib/agentmall/agentmall.db \
  "SELECT COUNT(*) AS 商品数 FROM products; SELECT COUNT(*) AS 商户数 FROM merchants;"
```

> ⚠️ 想让商品是 `products_real.json` 的版本，必须把仓库根的 `data/` 目录一起拷过去
> （§4.2 的 `cp -a` 已经带上了）。少了它页面会变成 30 条老种子，不报错，只是不对。

### 4.5 配环境变量

```bash
sudo tee /etc/agentmall/agentmall.env > /dev/null <<'EOF'
# ===== AgentMall 运行环境变量 =====
# 由 systemd 的 EnvironmentFile= 加载。权限必须 600 root:root（里面有公网域名）。
# ⚠️ 改成你自己的真实公网域名，这是支付收银台链接的对外 base URL。

# SQLite 路径：放在代码目录之外，好备份、好隔离权限
AGENTMALL_DB=/var/lib/agentmall/agentmall.db

# 对外 base URL（https + 域名，不要带结尾斜杠）
AGENTMALL_PUBLIC_URL=https://mall.example.com

# 端口（user 面这个是空转变量，真正的端口在 systemd 的 --port 里）
AGENTMALL_WEB_PORT=8000
AGENTMALL_MCP_PORT=8001
AGENTMALL_ADMIN_PORT=8002

# 管理后台路径前缀——用 nginx 挂在 /admin 下时必填。
# nginx 的 proxy_pass 尾斜杠会剥掉 /admin 前缀再转发给应用，
# 应用收到的是根路径 /orders、/logout；这个变量让它生成 /admin/... 的链接。
# 忘了设：后台导航会跳到用户面的同名路由（后台一点变成买家页面）。
AGENTMALL_ADMIN_BASE_PATH=/admin
EOF
sudo chmod 600 /etc/agentmall/agentmall.env
sudo chown root:root /etc/agentmall/agentmall.env
```

Docker 方式不需要这个文件，改用仓库根的 `.env`（见 §3.2）。

### 4.6 装 systemd unit 并启动

```bash
sudo cp deploy/agentmall-{web,mcp,admin}.service /etc/systemd/system/
sudo systemctl daemon-reload
sudo systemctl enable --now agentmall-web agentmall-mcp agentmall-admin

systemctl status agentmall-web --no-pager
journalctl -u agentmall-web -n 50 --no-pager
curl -s localhost:8000/healthz; echo
curl -s localhost:8001/healthz; echo
curl -s localhost:8002/healthz; echo
```

> 三个 unit 共用 `/etc/agentmall/agentmall.env`，所以 `AGENTMALL_MULTI_ROLE=1`
> 写在 `agentmall-mcp.service` 的 `Environment=` 里（覆盖优先级高于 EnvironmentFile）。
>
> ⚠️ 改了 env 文件后要 `sudo systemctl restart agentmall-{web,mcp,admin}` 才生效。
> ⚠️ **不要用 `scripts/start_demo.sh` 上公网**：它是本地路演脚本，前台跑、
> 不管属主、不设鉴权边界；公网一律走 systemd。

## 5. 配 nginx + HTTPS

### 5.1 装配置

```bash
sudo mkdir -p /etc/nginx/snippets
cp deploy/nginx.conf /etc/nginx/conf.d/agentmall.conf
```

**为什么放 `conf.d/` 而不是 `sites-enabled/`**：配置里有 `upstream{}` 和 `map{}`，
这两个指令**只能在 `http{}` 上下文**出现。`sites-enabled/*` 是 server 级上下文，
放进去 `nginx -t` 会直接报 `upstream directive is not allowed here`。

### 5.2 写公共 proxy 头片段

`deploy/nginx.conf` 里三处 `include /etc/nginx/snippets/proxy_common.conf;`
需要这个文件（内容见 `deploy/nginx.conf` 末尾注释）：

```bash
sudo tee /etc/nginx/snippets/proxy_common.conf > /dev/null <<'EOF'
proxy_http_version 1.1;
proxy_set_header Host              $host;
proxy_set_header X-Real-IP         $remote_addr;
proxy_set_header X-Forwarded-For   $proxy_add_x_forwarded_for;
proxy_set_header X-Forwarded-Proto $scheme;
proxy_set_header X-Forwarded-Host  $host;
proxy_set_header Connection        "";
proxy_connect_timeout 5s;
proxy_send_timeout    60s;
proxy_read_timeout    60s;
proxy_next_upstream   error timeout http_502 http_503;
EOF
```

### 5.3 改域名

`deploy/nginx.conf` 里把 `mall.example.com` 全部替换成你的域名：

```bash
sudo sed -i 's/mall\.example\.com/mall.yourdomain.com/g' /etc/nginx/conf.d/agentmall.conf
```

### 5.4 管理后台基础认证（**先做，再 reload**）

```bash
sudo apt install -y apache2-utils
sudo htpasswd -c /etc/nginx/.htpasswd opsadmin    # -c 只在第一次建文件时用！
sudo chmod 640 /etc/nginx/.htpasswd
sudo chown root:www-data /etc/nginx/.htpasswd
```

> 理由：管理后台目前没有独立账号体系——登录页收的就是管理员 key，
> 而默认 key `ak_demo_admin_secret` 是硬编码在代码里的，**登录页还会把它当 demo 提示回显**。
> 在补上账号体系之前，公网入口必须先用基础认证挡一层。应用层的 admin key 校验仍生效，是双保险不是替代。
>
> ⚠️ **htpasswd 文件不存在不会让 `nginx -t` 失败**，而是访问 `/admin` 时报 500。
> 「登录框一直转圈 / 500」先查这个文件在不在。

### 5.5 签发证书并启用 HTTPS

```bash
# 80 端口的 ACME 校验路径已在 deploy/nginx.conf 里放行（location ^~ /.well-known/acme-challenge/）
sudo systemctl reload nginx
sudo apt install -y certbot python3-certbot-nginx
sudo certbot certonly --webroot -w /var/www/html -d mall.yourdomain.com
sudo certbot renew --dry-run     # 验证自动续期真的能跑通（这步别省）
```

签发后确认 `/etc/nginx/conf.d/agentmall.conf` 里 `ssl_certificate` 指向
`/etc/letsencrypt/live/mall.yourdomain.com/fullchain.pem`（用 **fullchain**，
不是 `certificate.pem`，否则部分客户端报"证书链不完整"），然后：

```bash
sudo nginx -t && sudo systemctl reload nginx
```

### 5.6 验证

```bash
curl -I https://mall.yourdomain.com/ | head -5
curl -s  https://mall.yourdomain.com/mcp  -o /dev/null -w 'mcp: %{http_code}\n'
curl -s  https://mall.yourdomain.com/mcp/whoami -H 'Authorization: Bearer uk_demo_user_secret'
curl -I  https://mall.yourdomain.com/admin/        # 应返回 401（要 basic auth）
curl -s  -u opsadmin:你的口令 https://mall.yourdomain.com/admin/ -o /dev/null -w 'admin: %{http_code}\n'
```

## 6. 演示 key 清单（**演示用，上线必换**）

来自 `agentmall/db.py` 的 `SEED_*`，首次启动自动写入数据库。

| 角色 | ID | key / 账号 | 说明 |
|---|---|---|---|
| 买家（用户） | `U001` | `uk_demo_user_secret` | MCP 请求头 `Authorization: Bearer uk_demo_user_secret` |
| 买家登录账密 | `U001` | 用户名 `demo` / 密码 `demo123` | 用户面网页登录用 |
| 平台管理员 | `A001` | `ak_demo_admin_secret` | 管理后台登录页填这个 |
| 商户 M001 | `M001` | `mk_demo_m001_secret` | 日用优选生活馆 |
| 商户 M002 | `M002` | `mk_demo_m002_secret` | 洁美家居日杂 |
| 商户 M003 | `M003` | `mk_demo_m003_secret` | 个人护理专营店 |

> 🔴 **以上全部是硬编码在开源代码里的公开值，全世界都能查到。**
> 任何按 §8 换过 key 之前的公网部署，等于把平台管理权公开。

### MCP 客户端接入

- **URL（streamable-http）**：`https://mall.yourdomain.com/mcp`
- **鉴权**：`Authorization: Bearer <上表某个 key>`
- 快速自查某个 key 被解析成什么角色：

```bash
curl -s https://mall.yourdomain.com/mcp/whoami -H 'Authorization: Bearer mk_demo_m001_secret'
# → {"ok":true,"role":"merchant","actor_id":"M001","merchant_id":"M001","tools":[...]}
```

> key 决定调用方能看到哪些 tool（`agentmall/auth.py` 的 `ROLE_TOOLS`）：
> user 只能搜/下单/查自己的单，merchant 只能管自己店的商品和订单，
> admin 才能审核/下架/看审计。越权会被拒并**记进审计日志**。

### 换 key 的正确做法（不要改代码）

key 是数据库里的行，不是环境变量。直接改库：

```bash
sudo -u agentmall sqlite3 /var/lib/agentmall/agentmall.db <<'SQL'
-- 1) 换一个自己的随机 key（32 字节十六进制，自己用 uuidgen/openssl rand -hex 32 生成）
UPDATE admin_keys SET api_key = 'ak_' || <你自己的随机串>  WHERE id = 'A001';
UPDATE merchants SET api_key = 'mk_' || <你自己的随机串>  WHERE id = 'M001';
UPDATE merchants SET api_key = 'mk_' || <你自己的随机串>  WHERE id = 'M002';
UPDATE merchants SET api_key = 'mk_' || <你自己的随机串>  WHERE id = 'M003';
UPDATE users    SET api_key = 'uk_' || <你自己的随机串>  WHERE id = 'U001';
-- 2) demo 用户的口令也要换（PBKDF2 口令哈希）
UPDATE users SET password_hash = '<用下面脚本重新生成>' WHERE id = 'U001';
SQL
```

改完重启服务即可生效（key 每次请求现查库，无缓存）。

> ⚠️ `U001/demo` 这个账号口令是 `demo123`，**改 key 不改口令等于没换**，
> 网页登录照样能用弱口令进。网页登录用的是 `users.password_hash`，
> 生成新哈希：
> ```bash
> cd /opt/agentmall && sudo -u agentmall .venv/bin/python -c \
>   "from agentmall.auth import hash_password; print(hash_password('你的新口令'))"
> ```
> 把输出粘回上面那条 `UPDATE`。

## 7. 上线前安全清单（逐条打勾）

### 7.1 凭据

## 8. 备份与恢复

### 8.1 备份（**在线热备，不需要停服**）

WAL 模式下直接 `cp agentmall.db` 会拿到不一致快照（漏掉还在 `-wal` 里的事务），
必须用 SQLite 自带的 `.backup`：

```bash
# Docker 方式（data 在宿主目录，直接在宿主执行）
sqlite3 ./data/agentmall.db ".backup './data/backup-$(date +%F-%H%M).db'"
ls -lh ./data/backup-*.db

# systemd 方式
sudo -u agentmall sqlite3 /var/lib/agentmall/agentmall.db \
  ".backup '/var/backups/agentmall/agentmall-$(date +%F-%H%M).db'"
```

> `.backup` 会自动把 `-wal` 里已提交的事务一并写进目标文件，备份期间不阻塞写入。

**建议加个每日定时任务**（写进 crontab：`* * * * *` 那类，注意用绝对路径）：

```bash
0 3 * * * /usr/bin/sqlite3 /var/lib/agentmall/agentmall.db \
  ".backup '/var/backups/agentmall/agentmall-$(date +\%F).db'" \
  && find /var/backups/agentmall -name 'agentmall-*.db' -mtime +14 -delete
```

异地同步：`rsync -avz /var/backups/agentmall/ user@backup-host:/backup/agentmall/`

### 8.2 恢复

```bash
sudo systemctl stop agentmall-web agentmall-mcp agentmall-admin   # 必须先停服

sudo -u agentmall cp /var/backups/agentmall/agentmall-2024-xx-xx.db \
                       /var/lib/agentmall/agentmall.db
sudo -u agentmall rm -f /var/lib/agentmall/agentmall.db-wal \
                            /var/lib/agentmall/agentmall.db-shm
sudo chown agentmall:agentmall /var/lib/agentmall/agentmall.db
sudo chmod 600 /var/lib/agentmall/agentmall.db

sudo systemctl start agentmall-web agentmall-mcp agentmall-admin
sudo -u agentmall sqlite3 /var/lib/agentmall/agentmall.db \
  "PRAGMA integrity_check; SELECT COUNT(*) FROM products;"
```

> ⚠️ 覆盖 `.db` 之后**一定要删掉旧的 `-wal` / `-shm`**，
> 否则 SQLite 会拿新库去套旧 WAL，轻则数据错乱、重则直接报 `database disk image is malformed`。

## 9. 常见故障排查

| 现象 | 可能原因 | 定位命令 | 处理 |
|---|---|---|---|
| `Address already in use` / 服务起不来 | 端口被占（多半是本机重复起了两套） | `sudo ss -lntp \| grep -E '8000\|8001\|8002'` | `sudo fuser -k 8000/tcp`；确认 Docker 和 systemd **只跑一套**（两套都占同一组端口，必有一个抢不到） |
| `unable to open database file` | 目录属主与运行用户不符（Docker 下最常见） | `ls -ldn ./data` | Docker：`sudo chown -R 10001:10001 ./data`；systemd：`sudo chown -R agentmall:agentmall /var/lib/agentmall` |
| `database is locked` | 三进程同时启动撞 WAL 切换锁 | `sudo -u agentmall sqlite3 $AGENTMALL_DB "PRAGMA journal_mode;"` | 多数是瞬时，代码有 5 次退避重试；持续报说明 NFS/网络盘**不支持文件锁** → 必须换成本地磁盘 |
| `SQLite 目录在 NFS 上` | 文件锁不可靠 | `df -T /var/lib/agentmall` | 换成 ext4/xfs 本地盘；WAL 模式**不能**放 NFS |
| 数据看着「各服务各一份」 | 三个进程 `AGENTMALL_DB` 指向了不同文件 | `ps eww \| grep agentmall \| tr ' ' '\n' \| grep AGENTMALL_DB` | 统一成同一个绝对路径后重启三者 |
| 订单里的「去支付」链接打不开 | `AGENTMALL_PUBLIC_URL` 没设成公网域名（默认 `http://127.0.0.1:8000`） | `grep AGENTMALL_PUBLIC_URL /etc/agentmall/agentmall.env` | 改成 `https://mall.yourdomain.com`，**重启 web 和 mcp**（payment.py 在 import 时读一次该值） |
| **MCP 连不上 / 502 / 超时** | 没走 nginx；或 `proxy_buffering` 没关 | `curl -s https://域名/mcp/whoami -H 'Authorization: Bearer ...'`；`sudo tail -f /var/log/nginx/error.log` | 确认经 443 访问；检查 `/mcp` 段有 `proxy_buffering off` + `proxy_read_timeout 3600s` + `proxy_http_version 1.1` + `gzip off` |
| **MCP 连上了但几十秒后断** | `proxy_read_timeout` 没调（默认 60s 掐断 SSE） | `nginx -T \| grep -A5 'location = /mcp'` | 调大到 3600s；SSE 需要持续心跳，`proxy_send_timeout` 同步调大 |
| **MCP 返回 401 / 退化成匿名** | `Authorization` 头丢了 | `nginx -T \| grep -i 'proxy_set_header Authorization'` | 确认 `/mcp` 段有 `proxy_set_header Authorization $http_authorization;`，且中间没有 CDN/WAF 剥头 |
| MCP 报 `Task group is not initialized` | 用了 `uvicorn` 之外的方式加载（如 gunicorn 多 worker） | `ps -ef \| grep agentmall` | 必须单进程单 worker（session manager 挂在 lifespan 的 task group 里），不要 `-w 4` |
| `systemctl status` 显示 active 但页面 502 | 进程秒退又重启（最典型：`python -m agentmall.web.app`） | `journalctl -u agentmall-web -n 100` | `app.py` 没有 `__main__` 块，必须用 `uvicorn agentmall.web.app:app`（unit 里已是此写法） |
| `/admin` 一直 401 | htpasswd 口令错，或 basic auth 没带上 | `curl -I https://域名/admin/`；`sudo cat /etc/nginx/.htpasswd` | 口令错就 `sudo htpasswd /etc/nginx/.htpasswd opsadmin` 重设 |
| `/admin` 返回 500 | `.htpasswd` 文件不存在/权限不对 | `sudo ls -l /etc/nginx/.htpasswd` | `chmod 640` + `chown root:www-data`；注意 `nginx -t` **不会**发现这个问题 |
| `/admin` 里点导航跳到用户面页面 | 管理后台模板用的是根绝对路径（`href="/orders"`），前缀 `/admin` 被丢掉了 | 检查 `/admin` 段有没有 `proxy_redirect` + `sub_filter` | 见 §10.2；或者更省事：**用独立子域名**访问后台（见 §10.1） |
| 证书报错 `ERR_CERT_COMMON_NAME_INVALID` | 域名没解析到本机 / 用错了 `certificate.pem` | `dig +short 域名`；`openssl x509 -noout -text -in <证书> \| grep -A1 'Subject Alternative Name'` | 修 DNS；改用 `fullchain.pem` |
| 证书 90 天后过期 | 自动续期没生效 | `sudo certbot renew --dry-run`；`sudo systemctl list-timers \| grep certbot` | 确认 `certbot.timer` 是 enabled；80 端口的 ACME 路径不能被 301 到 https 拦掉 |
| 内存不足 / OOM 被杀 | 2G 机器跑三进程紧张 | `free -h`；`dmesg -T \| grep -i 'killed process'` | 加 2G swap：`sudo fallocate -l 2G /swapfile && sudo chmod 600 /swapfile && sudo mkswap /swapfile && sudo swapon /swapfile` |
| 磁盘写满 | SQLite `-wal` 不回收 / 日志膨胀 | `df -h`；`ls -lh $AGENTMALL_DB*` | 定期 `PRAGMA wal_checkpoint(TRUNCATE);`；journald 设 `MaxRetentionSec` |
| 首次启动商品是 30 条老种子 | `data/products_real.json` 没带上 | `ls -l /opt/agentmall/data/products_real.json` | 补上该文件（Docker 要重建镜像），清库后重启重新 seed |

### 10.2 已知限制（准备物料时核对代码发现的，**不是配置疏漏，是代码现状**）

1. **`AGENTMALL_WEB_PORT` 是空转变量**：`agentmall/web/app.py` 不读它，
   全仓只有 `scripts/start_demo.sh` 读。用户面端口只能靠启动命令的 `--port`。
   建议后续给 `app.py` 补一个 `main()`（与另两个模块对齐）。

2. **`agentmall/web/app.py` 没有 `__main__` 块**：`python -m agentmall.web.app` 会秒退且退出码 0，
   systemd `Restart=always` 下变成无限静默重启。本文档与 unit 统一用
   `uvicorn agentmall.web.app:app` 启动。

3. **管理后台的页面路径是根绝对路径**：模板里写死 `href="/orders"`、`action="/products/xxx/review"`，
   而用户面**恰好也有** `/orders`、`/login`、`/logout`。所以把后台挂在子路径 `/admin` 下，
   必须靠 nginx 的 `proxy_redirect`（改 Location 头）+ `sub_filter`（改正文里的 href/action）两条一起兜，
   配置里已配好。管理后台模板是自包含的（CSS 内联在 `<style>` 里，不引 `/static/`），全量改写不会误伤静态资源。
   **更稳的做法**：给后台单独一个子域名，此时不需要任何改写：

   ```nginx
   server {
       listen 443 ssl;
       server_name admin.mall.yourdomain.com;
       ssl_certificate     /etc/letsencrypt/live/admin.mall.yourdomain.com/fullchain.pem;
       ssl_certificate_key /etc/letsencrypt/live/admin.mall.yourdomain.com/privkey.pem;
       auth_basic           "AgentMall Admin (restricted)";
       auth_basic_user_file /etc/nginx/.htpasswd;
       client_max_body_size 20m;
       location / {
           proxy_pass http://127.0.0.1:8002;   # 注意：**不带斜杠**，路径原样透传
           include /etc/nginx/snippets/proxy_common.conf;
           proxy_cookie_flags ~ secure httponly samesite=lax;
       }
   }
   ```

4. **MCP 与管理后台的监听地址写死 `0.0.0.0`**（`http_server.py` / `admin_app.py` 的 `main()`），
   没有命令行参数可改。systemd 部署必须靠防火墙/安全组兜底（unit 注释里给了 uvicorn 备选写法，
   代价是端口改由命令行给、对应环境变量不再被读）。

5. **三进程共用单个 SQLite 文件**：靠 WAL + `busy_timeout` 串行化，**不能放 NFS/网络盘**（文件锁不可靠），
   也不能横向扩多机。单机中小流量没问题；要横向扩必须先换 Postgres。

6. **`nginx.conf` 里的 `upstream` / `map` 只能在 `http{}` 上下文**，
   所以文件必须放 `conf.d/`，不能放 `sites-enabled/`（放错 `nginx -t` 会直接报错，不是运行期问题）。
