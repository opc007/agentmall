## 4. MCP Tools 接口定义（验收以此为准）

### search_products
- 参数：`keyword: str`（如"纸巾"），`category: str = ""`（纸巾/垃圾袋/清洁/收纳/个护，空=不限），`max_price: float = 0`（0=不限），`limit: int = 10`
- 返回：按价格升序的商品列表，每项含 `id / name / category / price / original_price / unit / stock`
- 逻辑：关键词模糊匹配 `name`，结果按 `price` 排序，截断到 `limit`

### get_product
- 参数：`product_id: str`
- 返回：单个商品全部字段；找不到返回 `{"error": "..."}`

### create_order
- 参数：`product_id: str`，`quantity: int`，`address: str`，`note: str = ""`
- 返回：`{order_id, items, total, address, status: "待支付", pay_url, created_at}`
- 逻辑：订单号 `AM` + 10 位大写随机；`total = price * quantity`；订单存内存 dict
- `pay_url` 现阶段为占位链接（如 `https://pay.example.com/mock/{order_id}`），**不得伪装成真实支付**

### get_order
- 参数：`order_id: str`
- 返回：订单对象；找不到返回 `{"error": "..."}`

## 6. 验收标准（"可用基础版本"的定义）

1. `python -m agentmall.server` 无报错启动
2. 搜索"纸巾"返回按价格排序的列表（含 8 个纸巾 SKU）
3. `create_order("P001", 2, "广西南宁市朝阳广场")` 返回订单号（`AM` 开头）、`total` 计算正确、`status` 为"待支付"、`pay_url` 非空
4. `get_order` 能查回该订单；查不存在的订单/商品返回 `error` 而非崩溃

## 7. 合规红线（必读，不可妥协）

1. **只做"辅助支付"**：智能体生成订单 → 用户本人点击支付链接付款。绝不实现自动扣款。
2. `pay_url` 是占位，演示时必须声明为演示数据，不得让用户误以为可真实付款。
3. 价格/库存以 seed 数据为准，对外统一口径为"演示数据"。
